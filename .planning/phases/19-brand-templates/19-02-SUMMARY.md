# Phase 19 Plan 02: Brand Pipeline Integration Summary

Batch runner applies watermark overlay and intro/outro concatenation as FFmpeg post-processing steps after main honeyclip processing completes.

## What Was Built

Integrated the brand modules from Plan 01 into the batch processing pipeline using a post-processing approach:

1. **FFmpeg Path Resolution** - Created `findFFmpegPath()` helper:
   - Prefers honeyclip's bundled FFmpeg in `build/bin/ffmpeg`
   - Falls back to system FFmpeg via PATH
   - Follows existing pattern from `render/previews.nim`

2. **Watermark Post-Processing** - Created `applyWatermark()` proc:
   - Applies after main honeyclip subprocess completes successfully
   - Uses FFmpeg overlay filter generated by `brand/watermark.nim`
   - Builds command: `ffmpeg -i video -i watermark -filter_complex "overlay" -c:a copy output`
   - Temp file pattern with atomic rename for safety
   - Missing watermark image logs warning but doesn't fail batch

3. **Intro/Outro Post-Processing** - Created `applyIntroOutro()` proc:
   - Applies after watermark overlay (if both configured)
   - Uses FFmpeg concat demuxer with list file from `brand/concat.nim`
   - Builds command: `ffmpeg -f concat -safe 0 -i concat_list.txt -c copy output`
   - Cleans up temp concat list file after processing
   - Failed concat logs warning but doesn't fail batch

4. **Brand Pipeline Integration** - Modified `processOneFile()`:
   - Processing order: main edit -> watermark -> intro/outro concat
   - Both post-processing steps use `discard` (return value logged internally)
   - Post-processing only runs if main subprocess succeeded

5. **Brand Configuration Logging** - Enhanced `batch.nim`:
   - Logs watermark image path if enabled
   - Logs intro/outro paths when configured
   - Logs caption style preset if set
   - Appears after template validation warnings

## Key Decisions

**Decision 1: Post-processing approach**
- **Chosen:** Apply brand operations as FFmpeg post-processing after main honeyclip subprocess completes
- **Alternative:** Modify main edit pipeline to integrate watermark/intro/outro filters directly
- **Rationale:** Post-processing is cleaner because:
  - Brand operations only apply in batch mode (template-driven)
  - Avoids touching complex and well-tested edit pipeline
  - Isolated and easier to test
  - File-based approach simpler than filter chain injection

**Decision 2: Processing order**
- **Chosen:** edit -> watermark -> intro/outro concat
- **Rationale:** Watermark must be applied before concat so that intro/outro clips aren't watermarked (only the main content gets the brand overlay)

**Decision 3: Graceful degradation**
- **Chosen:** Missing files or failed operations log warnings but don't fail the batch job
- **Rationale:** Brand operations are enhancements - if watermark or concat fails, the main edit still succeeded and the output is usable

## Technical Implementation

### Post-Processing Pipeline

Both post-processing procs follow the same pattern:

1. Check if operation is needed (return early if not)
2. Validate required files exist (log warning and return if missing)
3. Find FFmpeg path (log warning and return if not found)
4. Generate temp output path with random suffix
5. Build and execute FFmpeg command
6. On success: remove original, rename temp to original
7. On failure: clean up temp file, log warning

## Performance Notes

- FFmpeg operations use `-c copy` for concat (stream copy, no re-encoding)
- Watermark overlay requires re-encoding (only video stream, audio copied)
- Post-processing happens sequentially per file after main edit
- Temp files use random suffixes to avoid collisions in parallel processing
- Atomic rename ensures output file is never in partial state
