<feature>
  <name>Proxy Generation Unit Tests</name>
  <files>tests/unit.nim, src/render/proxy.nim</files>
  <behavior>
  Test suite "Proxy Generation" covering:

  **Encoder selection (selectProxyEncoder):**
  - CPU backend → libx264, ultrafast preset, crf mode, value "28"
  - CUDA backend → h264_nvenc, p1 preset, vbr mode, value "2M"
  - CoreML backend → h264_videotoolbox, veryfast preset, vbr mode, value "2M"

  **Path building (buildProxyPath):**
  - Standard path: "/videos/talk.mp4" → "/videos/talk_proxy.mp4"
  - Path with spaces: "/my videos/file.mp4" → "/my videos/file_proxy.mp4"
  - Different extension: "/dir/clip.mov" → "/dir/clip_proxy.mp4" (always .mp4 output)
  - No directory: "video.mp4" → "video_proxy.mp4"

  **FFmpeg arg construction (buildFFmpegArgs):**
  - CPU encoder: args contain "-c:v libx264", "-preset ultrafast", "-crf 28", "-tune fastdecode"
  - NVENC encoder: args contain "-c:v h264_nvenc", "-preset p1", "-b:v 2M", "-rc vbr"
  - All encoders: args contain "-vf" with "scale=1280:720:flags=fast_bilinear"
  - All encoders: args contain "-c:a aac", "-b:a 128k", "-movflags +faststart"
  - All encoders: args start with "-y" (overwrite)

  **Progress parsing (parseProgress):**
  - Standard line: "frame=1234 fps=60.5 time=00:01:23.45 speed=2.1x" → (progress ~83.4%, speed 2.1)
  - Zero time: "time=00:00:00.00 speed=0.0x" → (progress 0.0, speed 0.0)
  - No match: "Encoding started..." → (-1, -1)
  - High speed: "time=00:05:00.00 speed=8.5x" for 10min video → (progress 50.0, speed 8.5)
  </behavior>
  <implementation>
  Add import for `../src/render/proxy` and `../src/ml/gpu_runtime` at top of unit.nim.

  Create test suite "Proxy Generation" with individual test cases for each behavior group above.

  For encoder selection tests: Create GpuRuntime objects manually with each backend value and verify the returned EncoderConfig fields.

  For path tests: Call buildProxyPath with various input paths and check output strings.

  For FFmpeg args tests: Build EncoderConfig manually, call buildFFmpegArgs, verify key flags are present using `in` or `contains` checks on the returned seq.

  For progress tests: Call parseProgress with sample FFmpeg output lines and verify extracted values using checkApprox (from test_utils fixture) for float comparisons.

  Run with: `nimble test`
  </implementation>
</feature>
