**Step 2: Create `src/batch/checkpoint.nim`** with JSON checkpoint persistence.

```nim
import std/[json, os, times, sets, strformat]
```

Define types:
```nim
type
  FileResult* = object
    path*: string
    error*: string      ## Empty if successful

  CheckpointState* = object
    templatePath*: string
    inputPath*: string
    totalFiles*: int
    completed*: seq[string]
    failed*: seq[FileResult]
    startTime*: float64
    lastUpdate*: float64
```

Implement:
- `proc checkpointPath*(inputPath: string): string` -- Returns `.honeyclip-batch.json` in the input directory (or next to input file). Use `parentDir(inputPath) / ".honeyclip-batch.json"` for files, `inputPath / ".honeyclip-batch.json"` for directories.

- `proc newCheckpoint*(templatePath, inputPath: string, totalFiles: int): CheckpointState` -- Creates new checkpoint with current `epochTime()` as startTime.

- `proc saveCheckpoint*(state: CheckpointState, path: string)` -- Atomic save: write to `path & ".tmp"`, then `moveFile(tempPath, path)`. Use `pretty(%state)` for human-readable JSON. Wrap moveFile in try/except since Windows may fail on atomic rename if target exists -- in that case, `removeFile(path)` then `moveFile`.

- `proc loadCheckpoint*(path: string): CheckpointState` -- Parse JSON file into CheckpointState. If file doesn't exist, raise IOError.

- `proc hasCheckpoint*(inputPath: string): bool` -- Returns true if checkpoint file exists at expected location.

- `proc markCompleted*(state: var CheckpointState, filePath: string)` -- Add to completed list, update lastUpdate.

- `proc markFailed*(state: var CheckpointState, filePath: string, error: string)` -- Add FileResult to failed list, update lastUpdate.

- `proc pendingFiles*(state: CheckpointState, allFiles: seq[string]): seq[string]` -- Returns files not in completed or failed lists. Uses HashSet for O(1) lookup.

- `proc printSummary*(state: CheckpointState)` -- Print batch summary: total, completed, failed counts, elapsed time. If failed > 0, list each failed file with its error message.

**Step 3: Create `src/batch/runner.nim`** with parallel batch execution.

```nim
import std/[os, strformat, strutils, cpuinfo, times]
import malebolgia
import ./template
import ./checkpoint
import ./discover
import ../log
import ../util/bar

from ../log import BarType
```

Define types:
```nim
type
  BatchConfig* = object
    tmpl*: BatchTemplate
    inputPath*: string
    outputDir*: string
    jobs*: int
    resume*: bool

  BatchResult* = object
    path*: string
    success*: bool
    error*: string
    durationMs*: int64
```

Implement:

- `proc processOneFile(inputFile: string, tmpl: BatchTemplate, inputRoot: string, outputDir: string): BatchResult` -- Process a single file using the template settings.
  1. Generate output path via `generateOutputPath`
  2. Create output directory if it doesn't exist (`createDir(parentDir(outputPath))`)
  3. Build CLI args from template via `tmpl.toArgs()`, prepend input file, append `@["-o", outputPath]`
  4. Execute honeyclip as a subprocess using `osproc.execCmdEx` with the constructed args: `execCmdEx("honeyclip " & args.join(" "))`. This is the simplest approach -- each parallel worker spawns a honeyclip subprocess. This avoids shared state issues with the FFmpeg pipeline.
  5. Track duration, capture exit code and output
  6. Return BatchResult with success/failure

  IMPORTANT: The subprocess approach means each file gets its own FFmpeg pipeline in a separate process. This is the safest approach for parallelism because FFmpeg's internal state is not thread-safe. The main process orchestrates, workers are subprocesses.

  Alternative approach if subprocess doesn't work well: Use `osproc.startProcess` with `poParentStreams` option to avoid output buffering issues. Or use `execProcess` which is simpler.

  Actually, for a CLI tool processing video files, the most practical approach is:
  - Find the honeyclip executable path via `getAppFilename()`
  - Construct the command: `{exePath} {inputFile} {templateArgs}`
  - Run via `execProcess` or `execCmdEx`

- `proc runBatch*(config: BatchConfig)` -- Main batch orchestrator:
  1. Discover files via `findVideoFiles(config.inputPath)`
  2. Handle resume: if `config.resume` and checkpoint exists, load it and filter to pending files. Print resume message: "Resuming: {pending} files remaining ({completed} completed, {failed} failed)"
  3. If not resuming, create new checkpoint
  4. Determine worker count: `if config.jobs == 0: countProcessors() else: config.jobs`
  5. Print start message: "[batch] Processing {n} files with {workers} workers"
  6. Process files using malebolgia for parallelism:
     ```nim
     var m = createMaster()
     m.awaitAll:
       for file in filesToProcess:
         m.spawn processOneFile(file, config.tmpl, config.inputPath, config.outputDir) -> void  # Results collected via checkpoint
     ```
  7. IMPORTANT: Since malebolgia spawns tasks that run in parallel, checkpoint updates must be serialized. The simplest approach: collect all results first, then update checkpoint after awaitAll. This means checkpoint isn't updated per-file during parallel execution -- it's updated in batch after all parallel files complete.

     Better approach for long batches: Process files in chunks (e.g., `workers * 2` files per chunk). After each chunk completes, update checkpoint. This gives resume granularity without per-file locking.

     ```nim
     let chunkSize = max(1, workers * 2)
     for chunkStart in countup(0, filesToProcess.len - 1, chunkSize):
       let chunkEnd = min(chunkStart + chunkSize, filesToProcess.len)
       let chunk = filesToProcess[chunkStart ..< chunkEnd]

       var results: seq[BatchResult]
       var m = createMaster()
       m.awaitAll:
         for file in chunk:
           m.spawn processOneFile(file, config.tmpl, config.inputPath, config.outputDir) -> results

       # Update checkpoint after chunk
       for r in results:
         if r.success:
           state.markCompleted(r.path)
         else:
           state.markFailed(r.path, r.error)
       state.saveCheckpoint(cpPath)

       # Update overall progress
       echo &"[batch] Progress: {state.completed.len + state.failed.len}/{state.totalFiles} files"
     ```

  8. Print summary via `state.printSummary()`

**Step 1: Enhance `src/util/bar.nim`** with batch progress support.

Add new proc to Bar type for batch-mode titles:

```nim
proc startBatch*(bar: Bar, totalFiles: int, currentFile: int, filename: string, total: float) =
  ## Start progress for a file within a batch
  let basename = extractFilename(filename)
  let title = &"[{currentFile}/{totalFiles}] {basename}"
  bar.start(total, title)
```

This reuses the existing `start` proc but formats the title with the batch counter. The progress bar thread already handles ETA calculation, so per-file progress with batch counter "just works".

Also add a batch summary line helper:

```nim
proc batchSummary*(totalFiles, completed, failed: int, elapsed: float) =
  ## Print batch processing summary line
  let elapsedMin = elapsed / 60.0
  echo &"\n[batch] Complete: {completed + failed}/{totalFiles} files ({completed} succeeded, {failed} failed) in {elapsedMin:.1f} min"
```
